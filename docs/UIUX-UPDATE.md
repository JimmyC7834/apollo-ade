# ADE Shell Design GuideThis guide describes the current ADE shell prototype closely enough for another agent to reproduce it. The product is a conversation-led development environment, not a conventional IDE and not a decorative website.## Design principles1. Chat is the primary workspace.2. Files, terminals, browser previews, and diffs are temporary artifacts, not permanent IDE panels.3. Dense controls use neutral productivity-tool styling.4. Every visible color comes from semantic theme tokens.5. Codicons are used throughout.6. Controls should not shift nearby content when hovered, expanded, or closed.7. Modeless supporting UI should preserve access to chat.## Workspace modelThe interface has three independent workbenches.### Chat WorkbenchThe default and primary view. It contains:- Session Navigator- Markdown transcript- Expandable event chips- Prompt composer- Profile controls- Modeless context explorer### Modal WorkbenchA resizable floating workbench used to inspect artifacts.- Opens when a transcript reference or artifact action is clicked.- Retains tabs and split state when dismissed.- Supports horizontal and vertical two-pane splitting.- Each tab has a hover-only close button overlaid on its right edge.- Pinning moves a tab out of the modal and into the Pinned Workbench.### Pinned WorkbenchA persistent artifact dock.- Landscape: docked to the right of chat.- Portrait or narrow window: docked below chat.- Resizable from an invisible edge.- Landscape collapse: 32px icon strip on the right.- Portrait collapse: 32px tab bar at the bottom.- Clicking a collapsed tab or empty collapsed-bar space expands the dock.- In the right strip, the collapse/expand control is anchored at the bottom.- In the bottom bar, the collapse/expand control is anchored at the right.## App chromeThe titlebar is 42px high and has three fixed regions:```text[ADE menu] [workspace/branch / session] [theme][minimize][maximize][close]```### ADE menuOnly the ADE button opens the application menu. It contains:- New session- Command palette- Settings- About ADE- Quit### BreadcrumbThe middle label displays:```textworkspace/branch / session```It occupies the draggable titlebar region and truncates rather than pushing window controls away.### Window controls- Theme, minimize, maximize, and close always remain visible.- Each is 42px wide.- Window controls are inert in the browser prototype.- Close uses the destructive theme color on hover.## Session NavigatorThe Session Navigator belongs only to the Chat Workbench.### Collapsed state- Width: 32px including a 1px right border.- Icon grid column: 31px, matching the actual inner width.- Begins flush at the top with no inner padding.- Has no background or border; status icons float over the Chat Workbench.- Every workspace header and session row is exactly 32px high.- Session labels are hidden.- Workspace status dots appear only when the workspace group is collapsed.- There is no rounding on active or hover highlights.### Expanded state- Width: 264px.- Expands over chat on hover; it does not reflow chat.- Item structure:```text[[31px centered status icon][label][24px action]]```- Workspace header is one line:```textworkspace · branch```- Workspace groups are collapsible.- Clicking a session switches the visible transcript.- There are no divider lines or extra group margins.- Expansion restores a solid sidebar surface and shadow for label readability.- The active session does not use a row background highlight.### Session statuses- Markers are rounded squares rather than circles.- Default marker size: 12px.- Active-session marker size: 18px.- Running: flashing theme foreground/white.- Done: restrained theme-compatible blue.- Idle: muted gray.- Waiting for input: muted yellow.## TranscriptBoth user and agent content render Markdown.### User message- Uses a subtle card surface.- No border.- Rounded enough to distinguish the message without resembling a speech bubble.- Aligned slightly right with a left margin.### Agent message- Unboxed Markdown.- No ADE heading or avatar before every response.
- Uses normal readable prose with deliberate paragraph spacing.### ReferencesMarkdown links can target internal artifacts:```md[src/App.tsx](artifact:app)[browser preview](artifact:preview)[working diff](artifact:diff)[validation output](artifact:terminal)```Rules:- Preserve the custom artifact: protocol in the Markdown renderer.- Render references using blue font color only.- Do not add a background chip.- Clicking opens or activates the corresponding Modal Workbench tab.### Event chipsTool calls and state changes are compact pills between Markdown paragraphs.- One chip per event.- Shows Codicon, label, compact result, and chevron.- Clicking expands details inline beneath the chip.- Details may include command output and an artifact action.- Expanded details do not open another surface automatically.### Turn undo- A completed agent turn can expose an Undo this turn action.- The unit of undo is the complete set of files changed by that agent turn.- In this UX prototype, activating Undo removes the corresponding change event from the transcript.- Keep this action visually secondary and adjacent to the affected event sequence.### Diagnostics- Diagnostics are represented by a compact transcript chip with an issue count.- Clicking it opens a Diagnostics Artifact in the Modal Workbench.- The Diagnostics Artifact groups build, type, lint, test, and runtime issues.- Each row shows severity, message, source path, and diagnostic code.- Diagnostic colors use --status-waiting and other semantic theme tokens.## Prompt composerThe composer is centered and capped at 760px.### Input surfaceFirst row:```text[prompt input][microphone][send]```- Microphone simulates recording, then inserts mock transcription.- Send is disabled when the prompt is empty.- Draft attachments appear as removable chips above the input.- Dragging a file or folder over the composer highlights its border/surface.### Bottom control barThe bottom bar is separate from the input surface and exactly 32px high.Left controls are independent transparent buttons, not a segmented container:```text[attach][profile summary][context ring]                    [profile]```- No default border or background on the three left controls.- Each highlights independently on hover.- Profile summary is read-only:```textmodel · effort · maximum context```- Context usage is an unlabeled circular progress ring.- Clicking the ring opens a usage popover.- Profile selector has no leading icon.## ProfilesA Profile combines:- Name- Model- Reasoning effort- Maximum context size- Tools enabled/disabled- Skills enabled/disabled- Approval behavior: Ask, Auto, or BypassProfiles created in this prototype persist only for the current session.### Profile menu and editing- Each Profile row has a right-aligned edit icon.- The icon is absolutely overlaid and appears only while that row is hovered.- Its appearance must not change row width.- Intercept Radix pointer-down selection so clicking Edit does not activate the Profile first.- Editing opens the same configuration modal populated with existing values.### Tools and Skills subpagesTools and Skills are navigation rows on the main Profile page, not checkboxes.- Each row shows the number currently enabled.- Clicking opens an in-modal subpage.- The subpage has a Back button, search field, count, and Enable all / Disable all action.- Selection rows use no native checkbox.- Enabled rows show a right-aligned Codicon checkmark.- Disabled rows show no trailing indicator.- Clicking anywhere on a row toggles it.- Both subpages include local search with a clear button.## Context explorerThe Attach button opens a modeless file explorer in the empty chat area directly above the composer.### Placement- Same width as the composer.- Opens immediately above it with an 8px gap.- Does not cover the input or toolbar.- Session Navigator remains above it in z-order.- Height is capped at 280px or 36vh.### StructureThe explorer has no title header and no footer.
```text[previous][current path][close][location rail][flat directory contents]```### Location railOS-style shortcuts:- Recent- Downloads- Documents- Desktop- Pinned- C:- D:### Directory pane- Flat directory listing, not a tree.- Shows only immediate children.- Clicking a folder drills into it.- Previous returns through directory history.- Clicking a file opens it as a Monaco editor tab in the Modal Workbench.- Files and folders are draggable into the composer.- Dragging into the composer is the only way to attach explorer content.- The explorer has no title header and no instructional footer.- Previous, breadcrumb path, and Close share one compact 28px bar.- The explorer is modeless and occupies the available chat space above the composer.- The Session Navigator must remain above the explorer in z-order.## File artifactsFile-type artifacts render with Monaco Editor in both Modal and Pinned Workbenches.- .tsx uses TypeScript language mode.- .css uses CSS language mode.- Monaco automatically lays out when panes or docks resize.- The minimap is disabled.- Font size is 12px with 20px line height.- The editor follows the current light/dark theme.- Terminal, browser, and diff artifacts retain their specialized renderers.## Artifact tabs- Tab bars are exactly 32px high.- Tabs are content-sized, with an 80px minimum and 180px maximum.- Close buttons appear only on hover or focus.- Close buttons are absolutely overlaid on the label.- Showing the close button must not resize the tab.- Labels truncate beneath the overlay.- The Pinned Workbench collapse control is always anchored to the tab bar edge and cannot be pushed away by content-sized tabs.## Global searchGlobal Search uses the command palette surface and spans:- Sessions- Files- Artifacts- Transcript contentOpen it with:- Ctrl+K`- ADE menu → Command paletteResults identify their source type and show a compact status or metadata label.## Slash commandsTyping `/ at the beginning of an empty prompt opens command autocomplete above the composer.- Filter commands as the user types.- Use Up/Down arrows to change selection.- Enter inserts the selected command into the prompt.- Mouse selection is supported.- Each row shows the command in monospace and a concise description.- Example commands: /review, /diagnostics, /test, /summarize, /clear.## Session notifications- Inactive Sessions may show unread notification indicators when completed or waiting for input.- Notification state is distinct from lifecycle status.- A modeless toast appears at the lower-right for important completion events.- Toast actions may open the corresponding Session.- ADE menu → Debug notification triggers the mock toast for design testing.- Toast styling uses theme surfaces and stays above all workbenches.## Resizing### Modal Workbench- Uses native CSS resize: both.- Includes a subtle corner indicator.- Minimum and maximum dimensions prevent unusable states.### Pinned Workbench- Uses an invisible 8px pointer target.- Landscape: drag the left edge horizontally.- Portrait: drag the top edge vertically.- Constrain size between 24% and 65%.- No visible resize handle.## Styling### ToneUse restrained desktop-product styling:- Neutral warm light theme.- Neutral charcoal dark theme.- No gold branding.- No gradients or atmospheric backgrounds.- No glass effects.- Minimal shadows.- Small radii.- Borders only where they clarify structure.### Theme disciplineDo not hardcode UI colors outside theme definitions. Use:- --background`- `--foreground`- `--card`- `--popover`- `--primary`- `--secondary`- `--muted`- `--accent`- `--destructive`- `--border`- `--input`- `--ring`- `--sidebar`- `--status-done`- `--status-waiting`Monaco, terminal, diffs, statuses, menus, and overlays must derive colors from those tokens.### IconsUse `@vscode/codicons.- Wrap Codicons in a small local React factory.- Avoid mixing icon libraries.- Typical icon size is 12–16px.### ScrollbarsApply a consistent custom scrollbar globally:- 8px width and height.- Transparent track.- Square muted thumb.- Foreground thumb on hover.
- Support Firefox and Chromium/WebView.## Responsive behavior### Landscape- Chat and Pinned Workbench split horizontally.- Pinned size is user-controlled.- Collapsed pinned dock becomes a right-side icon strip.### Portrait or width below 760px- Chat occupies the upper region.- Pinned Workbench occupies 40% below by default.- Session Navigator spans only the Chat Workbench height.- Collapsed pinned dock becomes a bottom tab bar.- Context explorer location rail and file pane remain inside the composer width.## Interaction caveats1. This is a UI prototype; window controls and tools are simulated.2. Modal and pinned content use mock artifacts, not real filesystem content.3. Browser URLs are represented as artifact tabs rather than real embedded navigation.4. Profile creation is in-memory only.5. Session switching uses fixture transcripts.6. The context explorer uses a fixture directory map.7. Native PTY execution must not block the Tauri UI thread.8. Monaco must be bundled locally in production; its default CDN loader causes offline timeouts.9. cargo bloat can overwrite the Tauri-produced executable with a Cargo-only build that points at the development URL. Rebuild through the Tauri CLI afterward.10. Keep the custom Markdown URL transform; otherwise react-markdown strips the artifact: protocol.## Key dependencies- Tauri v2- React- Tailwind CSS v4- shadcn-style local components- Radix UI primitives- `react-markdown`- `@vscode/codicons`- Monaco Editor- xterm.js- Rust `portable-pty`- Rust `git2`## ValidationFor UI iteration, run:```powershellnpm run dev -- --host 127.0.0.1```Validate TypeScript without packaging:```powershellnpx tsc --noEmit```Do not run a production Tauri build unless packaging is explicitly requested.
